## Model routing for token efficiency — read this carefully

Treat the main conversation as a **director**, not a worker. The session's job is to read findings, make routing decisions, and dispatch work — not to edit files itself.

### Opus 4.7 — use when judgment is the bottleneck

- **Truth-audits** that require reading the tex against the report, applying pattern-052, weighing primary evidence, judging falsified-vs-verified.
- **Math/physics rederivations** (sign errors, dimensional analysis, OOM sanity checks, Bayes-factor factorization). The R35conf wave's two corrections (ΔNeff 0.40 not 0.27; P5 3.56% not 2.7%) came from Opus agents doing chain/count arithmetic.
- **Closure judgments on novel content** — when a finding is real and a fix is non-obvious (e.g., the P1A NJL replacement physics, the GALZONE estimand reframe).
- **The main session itself**, to direct the loop.

### Sonnet 4.6 — use for execution of pre-specified plans

- **Closure-wave agents** when the truth-audit has already laid out the exact edits. Sonnet implements the plan, runs `git diff` + grep verification, recompiles, renders.
- **Repo hygiene** (CHANGELOG entries, README fixes, version stamps, paper-side mirror copies).
- **Site QA sweeps** (every route, every link, every version string — Sonnet is faster and cheaper here).
- **The browser-driving submission/harvest sweeps** once the recipe is dialed in (and it is — see `~/.claude/scistack/astrostack/external-review-browser-loop/SKILL.md`).

### Haiku 4.5 — use for polling and rote checks

- **Watchers** (R−1 < 0.015 checks on the c15 pod; deploy-verify curl loops; "is the file done compiling yet?" polling).
- **Routine "open this URL and grep for that string" sweeps.**

### Truth-audit verdict schema

`VERIFIED / PARTIAL / OPINION / STALE / FALSIFIED / HOUSTON-DECISION` — see `EXT5_P*_TRUTH_AUDIT.md` for templates.

**Auto-falsify rules:**
- **June 2026 IS the current month.** arXiv IDs `25xx.xxxxx` and `26xx.xxxxx` are valid published preprints.
- **HD-6:** correction notes / "earlier draft" retention is deliberate policy — submission-day decision, not a finding.
- **HD-11:** DOI placeholders → submission-day decision.
- **Fisher F₀ = 1/8.98²** is a known PDF extraction artifact ("1/8.98²" extracts as "1/8.982"). Always check tex source. Falsified 6 rounds running; R35conf was the first round nobody raised it.
- **Version-decimal collisions** like "z=−18.1.34" — renderer artifacts; tex wins.
- **Pattern-052 (re-raise vindication):** a re-raised finding that was previously FALSIFIED auto-falsifies ONLY if the prior falsification cited primary tex/artifact evidence. If the prior dismissal was assumption-based, re-verify properly.

### Closure-wave mandatory verification (rule born at EXT5)

After every closure edit, the implementing agent must run:

1. `git diff --stat <file>` — confirm non-zero diff
2. Grep each inserted phrase in the file — confirm on disk
3. Grep each "old phrase that should now be gone" — confirm absent
4. Recompile (`pdflatex` ×2 + bibtex if needed) — confirm 0 errors / 0 undef / overfull ≤ pre-existing
5. `pdftoppm` -render every edited page — visual confirmation no overflow
6. **REDERIVE every number you write** — never hand-copy a number from an audit. The R35conf wave caught two audit estimates this way (ΔNeff was 0.27 in the audit, < 0.40 when computed from the 93,066 chain samples; P5 percentage was 2.7% in earlier copy, 3.56% from the corrected denominator).

Logged-but-not-applied closures (changelog comment says applied, body text still has the old phrase) are a recurring failure mode — happened twice on P3 and once on P4. The verification rules above are non-negotiable.
