(1) VERDICT: MAJOR REVISIONS

(2) ISSUES:

1. [MAJOR] Section 3.1 / Appendix A, positional join definition: the algorithm assigns each eligible DESI row only to its nearest anomaly cluster, then applies the 1″ cut. This is not equivalent to finding all DESI–cluster pairs within 1″ unless the input clusters are proven to be mutually separated by more than the match radius, or unless missed non-nearest associations are explicitly irrelevant to the catalog definition. The manuscript should either document the minimum/near-neighbor distribution of the 190,015 DESI-containing clusters, use an all-neighbors query, or state and validate that nearest-only association cannot change the 2,468/181 cohorts.

2. [MAJOR] Sections 2.1, 5.1, and Data Availability, historical anomaly substrate: the catalog’s scientific identity depends on a “frozen historical anomaly list,” but the manuscript gives too little information about how that list was produced, versioned, and quality-controlled. It is acceptable not to reconstruct the anomaly model, but ApJS readers need enough provenance to understand what population the 190,015 clusters represent, what threshold generated the 195,829 DESI anomaly rows, whether the inputs are final public artifacts, and whether any preprocessing or coordinate transformations could affect the recovery.

3. [MAJOR] Sections 3.3, 4.1, and 5.1, very large ZWARN attrition: removing 2,267 of 2,448 primary matches is the dominant selection effect, but the manuscript does not characterize which ZWARN bits dominate, whether these warnings arise from known DESI pipeline conditions, or whether the result is driven by a small number of failure modes. Because the final catalog is described as “warning-free anomaly candidates,” a table or figure giving the ZWARN-bit distribution for the rejected primary cohort is needed to make the selection interpretable.

4. [MAJOR] Sections 6.1 and 6.4, independence and reproducibility of validation: the “independent validator” partly reconstructs the strict cohort from 143 checkpoint parts generated by the same replay, but those checkpoint parts are not listed among the 11 release payload files. The manuscript should clarify exactly which artifacts are required to reproduce each audit, whether a user can validate the 181-row set without retaining the transient checkpoint directory, and whether an independent clean rescan from the three public inputs gives the same strict cohort without relying on intermediate products.

5. [MAJOR] Data Availability / release permanence: the primary public byte-level reference is a Hugging Face commit, while the AAS digital-asset DOI is not yet assigned. For an ApJS catalog paper, the final accepted version should provide a durable archival route for the catalog, dictionary, code, provenance, and manifest, and the manuscript should state the license and long-term access expectations for both the release bundle and the historical input tables.

6. [MINOR] Section 3.2 / Table 1, target-bit definition: the manuscript should cite the DESI targeting bitmask documentation or DR1 data model directly for bits 0, 1, 2, 60, and 61, and should specify the integer type used for endian-safe evaluation, since high bits 60 and 61 are involved.

7. [MINOR] Section 3.3, duplicate handling: the manuscript says all three cohorts already have unique cluster and TARGETID keys, so no tie-breaking is needed in the final cohort. It would be useful to report whether any duplicate candidates existed before the predicate-specific deduplication at any stage, or explicitly state that the ordering rule is only a deterministic safeguard.

8. [MINOR] Section 3.4 / Section 4.3, separation tail: the 11 matches above 0.1″ are appropriately flagged, but the paper should include their candidate IDs in a small table or appendix, not only the summary counts, because these are the cases most likely to require user scrutiny.

9. [MINOR] Section 4.2, negative redshifts: the two negative-z, ZWARN=0 rows are retained consistently with the stated selection, but the manuscript should report their DELTACHI2 and target classes or note whether they are included in the 170 high-coordinate-consistency subset, since users may otherwise treat them as simple display-rounding artifacts.

10. [MINOR] Table 3 / Data Availability, machine-readable table naming: Table 3 is a 12-row illustrative table in the text, but the Data Availability section says the full 181-row, 43-column table is prepared as machine-readable Table 3. This should be clarified as a machine-readable continuation of Table 3 or renamed to avoid ambiguity.

11. [MINOR] Sections 6.2 and 7, viewer audit: the public-viewer retrieval audit is useful but should be clearly separated from catalog validation, since viewer pages are not stable data products and the screenshot evidence is not necessary for reproducibility. The manuscript already partly says this, but the audit should not be over-weighted relative to FITS-row validation.

12. [MINOR] References and formatting: the references are not in standard AAS style, some entries appear to use future or nonstandard bibliographic metadata, and the DESI DR1 paper/data-model citations should be checked carefully before submission.

(3) The central claim—that the authors have produced a small, reproducible, public-DESI-ID candidate catalog from a historical anomaly-coordinate list—is broadly supported, but acceptance requires clarification of the nearest-neighbor matching definition, stronger provenance for the historical inputs, and a more transparent account of the ZWARN-dominated selection.
