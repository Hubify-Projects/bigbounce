## CRITICAL ADJUDICATION — Claude M1 (circularity / seed self-recovery of the sub-0.1″ excess)

### The referee's claim
The sub-0.1″ "association excess" (§3.5, Fig 1) is largely self-recovery: clusters contain a DESI member by construction, the match coordinate is the member-coordinate mean, so re-matching against the public DESI catalog recovers the seed member at ≪0.1″; the 60–120″ shift controls necessarily lose that self-recovery, so "170 observed vs 0.625 shifted within 0.1″" and "strong aggregate association evidence" overstate the experiment. Reframe as seed self-recovery, or add a control that breaks the member-coordinate dependence.

### (a) What is matched against what — VERIFIED, mechanism is real
- **Clusters contain a DESI member by construction.** §2.1 L140: "Exactly 190,015 have a survey-membership string containing `desi_dr1`"; L141: "190,005 are DESI-only clusters."
- **The match coordinate IS the member-coordinate mean, derived from the member's own DESI coordinate.** §2.1 L165–168: "The preserved upstream DESI inference code copies each anomaly row's `ra`/`dec` directly from the coadd FIBERMAP `TARGET_RA`/`TARGET_DEC` fields … The positional-deduplication code then computes cluster `ra_mean`/`dec_mean` from the member coordinates." §2.1 L174–176: "The cluster positions used here are the frozen ICRS means of those historical positional groups, with no coordinate transformation … beyond the spherical unit-vector representation used for matching."
- **The match target is the full public DESI catalog by `TARGET_RA`/`TARGET_DEC`; the seed rows are NOT excluded.** Table `tab:desi-fields` L216: `TARGETID`, `TARGET_RA`, `TARGET_DEC` → "public rejoin and angular match." §3.1 L239–242: within each block, apply the mask, "convert the remaining coordinates to unit vectors, and query the nearest cluster … Only matches within the predeclared 1″ radius are retained." Nothing removes the DESI object whose own `TARGET_RA`/`TARGET_DEC` seeded the cluster mean — that object is in the 28.4M-row catalog and is the nearest match at ~0″.
- **The core is single-member by construction.** §2.1 L189: "Exactly one released cluster has more than one historical anomaly member: `P3-DESI-000030`" — and that one row sits in the 0.1–1″ **tail** (0.979656″, `tab:tail-ids` L338). So essentially **all 170 core rows are single-member DESI clusters** ⇒ cluster mean = the seed member's own coordinate ⇒ self-recovery is exact, not approximate.
- **The paper's own numbers are the smoking gun for self-recovery.** §3.3 L527: "The median positional separation is 0.00127″." §3.4 L351–352: "The target-to-canonical-original-member separations have minimum, median, and 90th percentile **zero**." I.e. for ≥90% of released rows the recovered public target is at **zero** distance from the historical member — the recovered `TARGETID`'s coordinate literally equals the coordinate that defined the cluster centroid. This is re-identification of the seed, exactly as the referee says.

**⇒ The referee's mechanism is REAL and, if anything, understated: for the core it is exact self-recovery, not merely "≪0.1″."**

### (b) Does the shift control break or preserve the seed-coupling — it BREAKS it (which is the problem)
§3.5 L363–366: the control shifts "every one of the 190,015 cluster positions along great circles by 60 and 120″." Moving the centroid 60–120″ off its seed member destroys the self-recovery, which is exactly why the shifted count at 0.1″ collapses to ~0.625 (§3.5 L375). So the "170 observed vs 0.625 shifted at 0.1″" comparison is **"seed present" vs "seed removed"** — a tautology, not an informative null **for the core**. The shift control is genuinely informative **only for the 0.1–1″ tail** (genuine chance coincidence: 11 observed vs 75.56 shifted, L376–377), where it correctly shows no secure identity.

### (c) Does the paper CLAIM an independent excess, or frame it as recovery? — it CLAIMS an excess
The paper does **not** frame the sub-0.1″ result as expected-by-construction recovery. It repeatedly presents the shift-control comparison as an informative test the core *passes*, yielding *evidence*:
- §3.5 L377–378: "Thus the sub-0.1″ core has **strong aggregate association evidence**, but the 11-row tail does not acquire secure candidate-level identity …"
- Fig 1 caption L389: "Logarithmic count axes **expose the sub-0.1″ observed excess** without hiding the chance-compatible 0.1–1″ tail."
- §7 "Third" L719–720: "**Local shifts support the aggregate association** of the sub-0.1″ core …"
- §8 Conclusions L757–758: "Deterministic local shifts **show that the sub-0.1″ core is an aggregate association excess** …"

The coordinate **lineage** is disclosed (§2.1 L165–176; §8 L744–745) and is used to hedge **identity** ("does not … prove object identity for a positional association," L173–174). But disclosing the lineage is **not** the same as disclosing that the §3.5 **excess itself is tautological**. The paper never states that the sub-0.1″ shift-control excess is expected by construction; instead it asserts the opposite framing ("evidence," "excess," "local shifts support/show"). Per this audit's decision rule — *paper claims an independent association excess AND the referee's mechanism is real ⇒ GENUINELY-NEW-REAL* — and "when in doubt, GENUINELY-NEW-REAL":

### **VERDICT M1: GENUINELY-NEW-REAL** (interpretive; with a disclosed coordinate-lineage sub-component)
The r8 disposition (its MINOR-2 → DISCLOSED-RE-FLAG) validated the lineage disclosure and the "aggregate, not individual identity" hedge but **did not test whether the shift-control excess is informative for the core.** It is not — it is by-construction self-recovery — and the paper presents it as informative association evidence. The r9 escalation to MAJOR is correct.

### Minimal honest fix (feasibility checked against committed artifacts)
- **Option (i) "recompute the excess excluding seed members" is NOT cleanly computable and should not be attempted.** The 170 core rows are single-member DESI clusters (§2.1 L189), so there is **no non-seed centroid** to rebuild from and no way to "exclude the seed" without the recovered `TARGETID` that the recovery itself produces (the pre-recovery members carried internal hashes, not public keys — §2.1 L177–181). Excluding the seed is circular in the other direction.
- **Option (ii) reframe is the honest fix — computation-free, uses numbers already in the paper.** In §3.5 (and mirrored in Fig 1 caption L389, §7-Third L720, §8 L757), state explicitly that the sub-0.1″ recovery is the **expected signature of re-identifying the seed DESI members whose own `TARGET_RA`/`TARGET_DEC` define the cluster centroids** — cross-referencing the already-reported median match separation 0.00127″ (L527) and original-member separation ≈ 0 for ≥90% of rows (L351–352) — so the 170-vs-0.625 gap is **by-construction self-recovery, not independent astrophysical association evidence**, and the local-shift control is informative **only for the 0.1–1″ tail.** No new observation, computation, or reanalysis. **No fabrication:** every supporting number already exists in the manuscript.
