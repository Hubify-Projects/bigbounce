This is a referee report for The Astrophysical Journal Supplement Series, prepared from the perspective of a rigorous cosmology and theoretical physics reviewer. 

The manuscript presents a structural recovery and positional join of a historical anomaly catalog against the DESI DR1 redshift catalog, yielding 181 public-ID candidates. While the creation of a reproducible, public-key catalog is a valid contribution to ApJS, the manuscript in its current form reads more like an internal software audit log or a repository `README.md` than a scientific paper. It is heavily padded with version-control minutiae, shell scripts, and file paths, while simultaneously failing to define key physical and algorithmic concepts necessary for a standalone reader. Furthermore, the data provenance explicitly points to an outdated repository state, which is unacceptable for publication.

Below is the detailed itemization of required changes.

### 1. ESSENTIAL: Internal Version-History and Audit Language
* **Location:** Throughout the manuscript (e.g., Page 1, line 14; Page 2, footnote 2; Page 6, line 414; Page 13, lines 905-908).
* **Problem:** The manuscript is littered with internal version-control tags, build checkpoints, and review-log prose. Examples include: "forming the v3.2.0-r2 release audited in this v3.2.0-r15 manuscript", "clearly secondary v3.2.0-r5 warned-primary auxiliary table", "the r6 controls", and "the present manuscript is v3.2.0-r15, 5 patch releases ahead". This violates standard journal formatting and treats the published paper as a living software branch rather than a final archival document.
* **Required Fix:** Strip all internal version-history language, release-candidate tags (r1, r3, r5, r15, etc.), and bookkeeping placeholders from the narrative text. The published paper represents the final, canonical version of the work.

### 2. ESSENTIAL: Provenance Surface and DOI Mismatch
* **Location:** Section 7 (Data Availability), Page 13, lines 903–910.
* **Problem:** The text explicitly states that the provided Zenodo DOI (`10.5281/zenodo.21461888`) resolves to an *older* version of the work (`v3.2.0-r10`), and that the current manuscript (`v3.2.0-r15`) is "5 patch releases ahead, and will be added to the same Zenodo concept record as a new version on the next re-stage." A published paper cannot point to a stale repository state with a promise to upload the correct artifacts in the future.
* **Required Fix:** The cited DOI must resolve to the exact, frozen artifacts, code, and data corresponding to the accepted version of this paper. Update the repository, mint the final DOI, and remove all language describing future "re-stages."

### 3. MAJOR: Scope, Length, and Structural Padding
* **Location:** Section 6.3 (Page 10), Section 6.4 (Page 10), and Data Availability (Page 12, lines 827–844).
* **Problem:** The paper is 17 pages long, which is excessive for a 181-row positional join. The text is heavily padded with material that belongs in a digital repository, not a journal article. This includes exact HTTP ETags ("ETag of 6a516695-5356e87c0"), raw shell script blocks (Page 12), exhaustive lists of file paths (`pipelines/p3_anomaly_engine/outputs/...`), and byte-count audits.
* **Required Fix:** Restructure the paper. Move all shell scripts, file manifests, byte counts, and SHA-256 hashes to a `README.md` file within the Zenodo deposit. The main text should describe the scientific and algorithmic methodology, not the transaction-level execution of the pipeline.

### 4. MAJOR: Missing Effect Sizes and Statistical Tests
* **Location:** Section 4.1, Page 6, lines 440–445.
* **Problem:** The text compares the medians and interquartile ranges of the accepted versus warning-bearing cohorts (e.g., $z = 1.10842$ vs $0.88605$, DELTACHI2 = $61.0634$ vs $4.91948$). However, no statistical tests are performed to determine if these distributions are significantly different, nor are effect sizes provided.
* **Required Fix:** Every juxtaposition of descriptive statistics intended to demonstrate a difference must be accompanied by a rigorous statistical test (e.g., a two-sample Kolmogorov-Smirnov test) and a standardized effect size (e.g., Cohen's $d$ or Cramér's $V$). 

### 5. MAJOR: Standalone-Reader Test Failure
* **Location:** Section 2.1, Page 2, lines 114–115.
* **Problem:** The text states: "It is the frozen $S > 5$ canonical-S selection from the DESI-trained BigAE stream". The terms "canonical-S" and "BigAE" are load-bearing concepts that define the input sample, yet they are never defined in the text. Relying entirely on a citation ([5]) for the fundamental definition of the input data violates the requirement that the paper be self-contained.
* **Required Fix:** Provide a concise, explicit definition of the "BigAE" model architecture and the "canonical-S" metric within the text so that a reader can understand the physical/algorithmic nature of the anomaly scores without opening another paper.

### 6. MINOR: Uncomputed Quantitative Claims
* **Location:** Section 3.5, Page 5, line 374.
* **Problem:** The text asserts that "the recovered public object is, by construction, at essentially the member coordinate that defined the centroid." The word "essentially" is a qualitative placeholder for a checkable number.
* **Required Fix:** State the exact numerical tolerance or maximum separation (in arcseconds or micro-arcseconds) that justifies the word "essentially."

### 7. MINOR: Qualitative Association Claims
* **Location:** Section 4.1, Page 6, line 451.
* **Problem:** The text claims that the contrasts "show that the gate is associated most directly with fit discrimination". "Associated most directly" is an unquantified assertion.
* **Required Fix:** Compute and report the correlation coefficient or relevant association metric that proves this gate dominates the variance compared to other available metadata.

## Summary recommendation
MAJOR REVISIONS

The core deliverable—a reproducible, public-ID catalog of DESI anomalies—is appropriate for ApJS and the positional join methodology is sound. However, the manuscript is currently written as an internal software-engineering audit rather than a scientific paper. It requires a severe structural edit to remove version-control artifacts, shell scripts, and file paths, moving them to the data repository. Furthermore, the data provenance must be updated so the DOI points to the exact artifacts of the final paper, and statistical claims must be backed by rigorous effect sizes and tests.
