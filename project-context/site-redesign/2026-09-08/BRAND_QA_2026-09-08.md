## Fix applied this session

`/status` reused the `PageHeader` component four times per page, and
`PageHeader` always rendered `<h1>` — a real heading-hierarchy violation
(items 3 and 8), not present on any other route. Root cause: `site/src/app/status/page.tsx`
calls `<PageHeader>` for "Research program status" (correct h1), then again
for "What 'ready' means", "Active compute", and "Survey QC" (should be h2).

Fixed:
- `site/src/components/primitives/PageHeader.tsx` — added an optional
  `level?: "h1" | "h2"` prop (default `"h1"`), renders `<Title>` where
  `Title = level`.
- `site/src/app/status/page.tsx` — passed `level="h2"` on the three
  in-page-section `PageHeader` calls, leaving the top one as the sole h1.

Same root-cause bug exists on `/publish` (5 `PageHeader` calls) — that route
is outside this sweep's route list, so it was **not** touched; flagged as a
background task instead (`site/src/app/publish/page.tsx`).

This fix is **fixed-pending-deploy**: committed and pushed, not yet live at
the time this report was written (Vercel needs a fresh deploy of `site/`).
Re-verify h1 count = 1 on `/status` after the next deploy lands.

## Three judgment calls

**Designed publication vs. styled app.** Yes, overall it now reads as a
designed publication rather than a styled app — the type scale is doing real
work (one big serif-adjacent display line per page, a quiet mono metadata
row for version/date/pages/target, restrained pill actions), the accent color
is used sparingly and consistently across both themes, and the band rhythm
gives most pages a paper-like cadence instead of a dashboard grid. The paper
detail page (`/papers/paper-a3m`) is the clearest evidence of this: it reads
like a journal cover page, not a SaaS product screen.

**Weakest page.** `/status` is the weakest page, and not only for the h1 bug
just fixed. It's the one place doing dashboard duty inside a publication
shell — four stacked sections (headline stats, per-paper table, five-gate
breakdown, compute, survey QC) each carrying their own dense sub-hierarchy of
badges, mono segments, and pill actions, so even after collapsing to one true
h1 the page still reads as "several small tools glued together" rather than
one composed page. It's also the highest nested-border-chrome count of any
route (16, mostly small status badges inside an already-bordered table row).

**Highest-leverage next change.** Give `/status` a real internal visual
hierarchy pass: turn the four `Band`s into a single scannable narrative (lead
stat row → paper table → collapsed/expandable gate detail → compute/QC as a
lower-priority footer strip) rather than four equal-weight sections, and swap
the repeated `badge-neutral` pills for a lighter inline treatment so the table
doesn't read as boxes-in-a-box. That single change would do more for "reads
as one designed page" than any other route on this list.
