## 0. Why this doc exists

The migration plan (`MIGRATION_BOUNCE_COSMOLOGY_LAB.md`) covers 4 papers, 53 experiments, 328K anomalies, 3 pipelines, ~$400 of GPU compute, and ~3 months of research. One wrong import step could corrupt or lose irreplaceable data.

This document specifies a **1-day rehearsal** on synthetic data. The test lab ("hubify-test-lab") uses ~100 fake experiments, 5 fake papers, 3 fake pipelines, and ~500 fake wiki entries. It exercises every step of the migration plan against zero-risk data.

**Decision rule:**
- All 9 steps pass → green light to begin real BigBounce migration
- Any step fails → fix the failure on the test lab → re-run from that step
- Never begin BigBounce migration until this protocol completes with all gates passing

### Step 2 — File-system import (target: 30 min)

This is the highest-risk step in the real migration. In the test lab, we validate the import script logic on throwaway data.

**What to run:**
```bash
# 1. Generate the 105 synthetic experiments
python3 synthetic/gen_synthetic_experiments.py --output experiments/ --count 105

# 2. Run the import script (dry-run first — this gate is required before real run)
python3 scripts/import_lab.py \
  --source synthetic/ \
  --lab hubify-test-lab \
  --dry-run \
  --verbose 2>&1 | tee /tmp/import-dryrun.log

# 3. Inspect dry-run output — must show correct classification
grep "CLASSIFY" /tmp/import-dryrun.log | head -20

# 4. If dry-run clean, run for real
python3 scripts/import_lab.py \
  --source synthetic/ \
  --lab hubify-test-lab \
  --verbose 2>&1 | tee /tmp/import-run.log
```

**Pass criteria:**
- [ ] Dry-run produces zero `ERROR` lines in log
- [ ] Dry-run classifies all 5 `.tex` files as `paper` type
- [ ] Dry-run classifies all 105 experiment JSONs as `experiment` type
- [ ] Dry-run maps experiments to correct projects (spot-check 5)
- [ ] Real run produces zero `ERROR` lines
- [ ] `experiments/` dir contains 105 JSON files after real run
- [ ] Each JSON has `migrated_from:` field pointing to the synthetic source path
- [ ] `papers/` dir contains 5 entries, each with `migrated_from:` field

**Fail action:**
- If classification wrong → fix the classifier regex in `import_lab.py` + re-run dry-run
- If `migrated_from:` missing → add it to the import script before re-running
- Never re-run the real import without a clean dry-run

**Critical anti-pattern to catch:** The import script must NOT overwrite an already-imported entity if re-run. Test this explicitly:

```bash
# Run import a second time — must be idempotent
python3 scripts/import_lab.py --source synthetic/ --lab hubify-test-lab --verbose 2>&1 | grep -i "skip\|already\|exist"
# Must see "already imported, skipping" for all 105 experiments
```

## 7. Appendix — `gen_synthetic_experiments.py` reference implementation

```python
#!/usr/bin/env python3
"""
Generate 105 synthetic experiment JSON files for the test-lab pre-validation protocol.
Output: experiments/EXP-SYNTH-{n:03d}.json  (105 files)
"""
import json, random, os
from datetime import datetime, timedelta

PROJECT_SLUGS = ["p-baseline","p-extensions","p-anomaly","p-chirality","p-pta","p-infra"]
# Distribution matches §1.2 spec
PROJ_COUNTS = {"p-baseline":30,"p-extensions":20,"p-anomaly":25,"p-chirality":15,"p-pta":10,"p-infra":5}
STATUSES = ["complete"]*70 + ["running"]*10 + ["queued"]*10 + ["failed"]*10
MODES = ["gpu·pod","gpu·srvless","cpu·pod","cpu·srvless"]

def gen(n: int, project: str) -> dict:
    created = datetime.utcnow() - timedelta(days=random.randint(0,90))
    return {
        "id": f"EXP-SYNTH-{n:03d}",
        "title": f"Synthetic experiment {n}: {project} test run",
        "project": project,
        "status": random.choice(STATUSES),
        "compute_mode": random.choice(MODES),
        "duration_hours": round(random.uniform(0.1, 48), 2),
        "cost_usd": round(random.uniform(0.5, 25), 2),
```
