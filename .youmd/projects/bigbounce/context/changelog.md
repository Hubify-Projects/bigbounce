# BigBounce change history

Use the existing evidence streams instead of maintaining a duplicate changelog:

- Program decisions and current phase: `ops/PLAN.md`
- Current and historical tasks: `project-context/tasks.md`
- Review/revision chronology: `project-context/peer-reviews/REVISION_TRACKER.md`
- Current portfolio board: `project-context/SSOT/index.md`
- Exact repository history: `git log`

You.md should capture durable context and pointers; exact review findings,
versions, receipts, and closures remain in their canonical ledgers.
